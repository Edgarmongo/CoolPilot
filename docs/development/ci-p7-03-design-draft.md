## 1. 原卡范围（主线 §13 442–447，逐字引用）

- `P7-03-01` 预估：预计模型、节点数、输入输出用量与费用区间；明确「预估不是保证价格」。
- `P7-03-02` 预算上限与超额提醒（本月预算、已用、预计月末支出、高成本任务）。
- `P7-03-03` 执行中持续累计实际成本，达到阈值暂停后续节点并交由用户决定（**不能只在前端显示提示**）。
- `P7-03-04` 三种执行策略（省成本 / 均衡 / 质量优先）必须真正影响工作流执行规则，而不是只切换一个模型名。

**本稿的范围口径**：本卡**不是**「一个预估函数 + 一个预算输入框」，而是
**预估 → 自然月预算 → 执行前决策 → 执行中累计与预留 → 暂停与恢复** 的闭环，且必须覆盖
**重试、并发执行与后续节点**（§13 原则 3）。只做预估模块、不接执行链路，视为**未交付**。

## 2. 完成标准（作者裁定稿，逐字采纳）

1. **生成前成本预估**：对支持估算的模型调用给出明确标注的预估成本；价格、用量或 Provider 路由信息不足时，返回未知或有依据的区间，不得将缺失信息视为零成本。
2. **自然月预算管理**：支持配置预算上限，并按自然月统计已发生费用、可解释的预估费用和预算剩余情况。实际费用与预估费用必须分开呈现。
3. **完整工作流预算**：预算检查覆盖工作流中的重试和后续节点，不能只检查第一个模型调用。并发执行时必须有明确的预算预留或等效机制，避免多个执行同时通过检查后造成不可控超支。
4. **执行前拦截**：在模型请求或后续工作流节点开始前执行预算决策。达到预算限制时，不得继续发起被禁止的调用。
5. **暂停与恢复**：预算策略要求暂停时，持久化足以恢复执行的状态；恢复后必须重新检查预算、价格和执行条件，不能绕过拦截直接续跑。
6. **调用账本一致性**：实际调用及每次重试继续遵循现有账本记录原则；预算预估、预留金额与最终账本费用能够区分和对账。
7. **本地优先与数据主权**：预算设置和相关状态遵循现有本地数据架构；不得将 API 密钥写入预算记录、日志或预估结果。
8. **自动化验证**：测试覆盖价格缺失、不同价格维度、估算上下界、重试、并发预算决策、请求发出前拦截、暂停与恢复，并证明未知金额不会被默认为零。

## 3. 预算时间范围（作者已裁定：自然月）

### 3.1 窗口定义

- 采用**自然月**，按**本地日期**从本月月初到下月月初，即窗口 = `[monthStart, nextMonthStart)`（本地时区构造 `new Date(y, m, 1)` 与 `new Date(y, m + 1, 1)`）。
- **不使用**滚动 30 天。现有 `usageRangeStart(days)`（`src/lib/usage.ts:9-27`）是滚动天窗口，**只在成本中心现有读侧继续使用**；预算侧需新增自然月窗口纯函数（不做表）。
- **月度切换**：新月份启用新的预算周期；**上月账本行保留**，不在新周期内重算，也不因切月删除。
- 原卡 `P7-03-02` 的「预计月末支出」= 本月已发生 + 本周期内剩余已知计划的预估；**必须标注推算依据**，数据不足时显示「无法推算」，**不得**显示 0。

### 3.2 四类金额分开呈现（完成标准 2 + 原则 2、9）

| 类别 | 来源 | 可求和 | 呈现纪律 |
| --- | --- | --- | --- |
| 已发生（可计价） | `ai_usage_ledger.cost_amount`，`cost_source` ∈ {`computed`, `provider-reported`} | 是 | 必须标注该金额是 `computed`（我们的算术）还是 `provider-reported`（供应商实收） |
| 未知 / 未计价 | `cost_source` ∈ {`unpriced`, `unknown`} 的行 | **否**（单独计数） | 显示行数与原因（无价格 / 维度不匹配 / 缺用量）；**不得当 0 参与求和**，**不得**显示为「0 元」 |
| 预估（待执行） | 预估层输出（§8 Slice 0） | 否 | 必须显示**区间**与依据（`estimateMethod`、价格版本、模型）；写明「预估不是保证价格」 |
| 预留 | 预留结构（§3.4） | 否 | 独立于「已发生」；**不得提前记作已发生的模型费用**；释放 / 核销规则必须可追溯 |

- 数据落点：本地 Workspace 既有 SQLite（原则 5）；预算相关记录**不保存** API Key、Cookie、完整提示词（原则 7 / 完成标准 7）。

### 3.3 与账本的关系（完成标准 6）

- 实际调用与每次重试**继续**按现有原则写 `ai_usage_ledger`（一次尝试一行，`src/db/schema.ts:521-522`、`src/lib/ai-usage-ledger-recorder.ts:25-32`）；**不改** C2 `recordPublishSuccess` 语义，**不改** AI Runtime 契约。
- 预估与预留**不进** `ai_usage_ledger.cost_amount`；两者通过「预算周期 + 运行标识（`runId`）/ 节点标识（`nodeId`）」与账本行对账（用例见 §9）。

### 3.4 预留与并发（完成标准 3）

- 「多个执行同时通过检查」是**真实风险**：`POST /api/runs`、定时计划与交互式请求之间**没有**共享闸门。
- 方案要求：**检查 + 预留 + 扣减在同一事务内完成**（本地 SQLite 同步事务）；预留只能由「开始执行」写入，由「结束 / 失败 / 取消」核销；**预留不得计入「已发生」**。
- 若作者不批准新增预算 / 预留表，本轮只能给出「上限校验 + 事后对账」的**弱化版本**，且**必须**在交付说明中写明「并发下可能超支」，**不得**声称已满足完成标准 3。

## 4. 暂停语义（作者已裁定：可持久化、可恢复的业务暂停）

> **总原则**：暂停 = **不再发起被禁止的调用** + 持久化足以恢复的状态；**不等于**中断一个已经发出的远程模型请求。已发出的调用只能按**实际返回 / 失败 / 超时**结果记账与处理，暂停**不会**抹掉已发生的费用（作者裁定）。

| 路径 | 拦截位置（对应现有代码位置） | 决策为「阻止」时的行为 | 必须持久化的状态 | 恢复时的强制要求 |
| --- | --- | --- | --- | --- |
| 单次交互式生成 | 调用 `aiRuntime.*` **之前**（14 个调用点，见 §10） | 请求发出前拒绝，返回可理解原因（错误码 + 原因 + 当时预算快照），**不产生**账本行 | 无需持久化运行（同步请求）；需留下**决策记录**（预算周期、阈值、拒绝原因） | 用户调整预算后重新发起，视为**新请求** |
| Agent 执行 | `src/lib/agent/langgraph-engine.ts:277-314` 工具循环 + `registry.requiresApproval()`（`src/lib/agent/tool-registry.ts:43-53`；工具自声明见 `src/lib/agent/contracts.ts:20`） | **复用**现有 `status:"paused"` + `pendingApproval`，经 `POST /api/agent/runs/[id]/resume` 恢复 | 现有 `agent_runs` 状态 + 暂停原因（预算）+ 当时预算 / 预留快照 | 恢复**必须重新检查**预算、预留、价格与剩余步骤，**不得**直接续跑 |
| 工作流 / 自动化任务 | `src/worker/runner.ts:257-287` `processRun` **每个节点执行前**（**当前无闸门，需新增决策点**） | 暂停后续节点（当前节点若已发出则按其实际结果记账），记录暂停原因 | 运行状态、已完成节点、待执行节点、已发生累计费用、预留与预算周期标识 | 重检预算 / 预留 / 价格；剩余节点按当前预算**重新决策** |
| 恢复执行（通用） | 恢复入口（API / 界面） | — | — | **不得**因为用户点击「继续」就跳过预算检查（完成标准 5） |

- **不可做的事**：不得假定「暂停 = 撤销成本」；不得在暂停期间继续发起模型调用；**不得**把预算决策只做成前端提示（原卡 `P7-03-03` 明写「不能只在前端显示提示」）。
- **需作者确认的边界**：「暂停」是否包含**取消**尚未开始的后续节点（本稿理解：暂停即不再发起后续节点，但**不**回滚已完成节点与其费用）。

## 6. 关键未决设计问题（需作者裁定后再动手）

### 6.1 预算与预留的存储位置

- **选项 A**：复用 `settings`（`src/db/repositories/settings.ts` 的 `readAppSetting` / `writeAppSetting`）——**只适合保存「本月预算上限」这类配置**；KV 覆盖写**无 CAS / 事务语义**，**无法**安全实现并发预留。
- **选项 B**：新增本地表（建议命名 `ai_budget_periods`（周期与上限）+ `ai_budget_reservations`（预留与核销））——可在**同一事务**内完成「检查 + 预留」。
- **本稿建议**：上限配置可先用 `settings`；**预留必须**走表 + 事务。若只批选项 A，则完成标准 3 **不达标**，且必须在交付说明中如实标注（§3.4）。
- **需作者裁定**：是否允许新增本地表与迁移。

### 6.2 预估的输入规模与区间口径

- 无 tokenizer → 采用**显式启发式**（如按字符数 / 语言权重的 v1 方法），输出**区间**（下界按输入字符估算；上界取 `maxTokens` 或模型上限），并携带 `estimateMethod` 与价格版本。
- **不得**把启发式结果表述为「实际用量」；预估**不写**账本费用列（§2.2 A）。
